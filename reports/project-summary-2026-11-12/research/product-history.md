# 제품 방향·고객 결과·진화 이력 조사

조사 기준: 2026-11-12, 현재 작업 트리와 명시된 과거 문서. 이 문서는 종합 PDF 작성을 위한 근거 메모다. 실제 상용 출시나 고객 효과를 새로 검증한 결과는 아니다.

## 1. 프로젝트가 추구하는 방향

NEXORA의 장기 방향은 사업자가 자신의 사업 맥락과 실제 근거를 이해한 뒤, 다음 행동을 고르고, 필요한 마케팅 작업을 제작·검토·실행하고, 관측 결과를 다음 판단으로 이어 가는 작업 공간이다. 현재 랜딩의 핵심 문구는 `From big questions to your next business move.`이며, 사업 체크·주간 계획·검토된 초안·실제 측정값을 맥락으로 연결한다고 설명한다. 단순히 조언 문장을 받는 것보다 한 번의 판단이 실제 업무와 다음 관찰로 이어지는 것을 추구한다.

그 연결은 다음 순환으로 구체화된다.

**상품·고객·채널·목표 확인 → 입력 근거와 모르는 점 구분 → 조사 방향/권장 행동 → 주간 과제 → 필요한 문구·소재 제작 → 사람의 수정·정확한 버전 승인 → 외부에서 실제 사용 → 기간·출처가 있는 측정 → 새 근거와 재진단.**

여기서 사업 체크는 규칙 기반 조사 제안이다. 원인을 확정하는 전문가 진단이나 미래 매출을 예측하는 검증 모델로 해석할 수 없다. 실제 AI 공급자 호출은 텍스트 제작에서 시작했다. 11/12에는 업로드 사진 기반 광고 레이아웃과 비공개 PNG/JPG 내보내기 코드가 추가됐지만, AI 이미지 생성·MP4·음성·AI 장면은 아직 미구현이다. 광고가 적절하지 않은 상황에서는 비용 검토·자료 수집 같은 비마케팅 행동도 제공한다.

핵심 설계 원칙은 다음과 같다.

| 원칙 | 실제 제품에 나타나는 방식 | 고객에게 주려는 가치 |
|---|---|---|
| 자신의 사업 맥락으로 시작 | 상품·고객·채널·사업 유형·단계·목표를 저장 | 같은 설명을 여러 도구와 다음 작업에 반복하는 부담을 줄일 기반 |
| 확인한 사실과 모르는 점 분리 | 자기보고 맥락, 측정값, 가설, 자료 부족을 구분 | 판단 근거를 이해하고 수정할 수 있음 |
| 사람의 판단을 중심에 유지 | 수정본을 새 버전으로 보관하고 정확한 버전 승인 | 무엇을 승인하고 사용할지 통제 |
| 업무를 이어서 끝내기 | 추천·계획·초안·승인·실제 사용·결과를 연결 | 분산된 관리 작업을 한 맥락에서 이어 갈 기반 |
| 기록과 성과를 분리 | 완료·다운로드를 매출/전환으로 환산하지 않음 | 실제 사업 변화와 활동량의 혼동 방지 |
| 과거 작업의 맥락 보존 | 진단 당시 프로필·근거, 초안 버전, 승인본 참고 스냅샷 | 지난 결정의 이유를 확인하고 다음 작업에서 참고 |

## 2. 초기 판매 방향과 장기 비전의 관계

공개 사이트는 서비스 사업, 온라인 매장, 크리에이터, 지역 사업자까지 폭넓게 소개한다. 내부 사업 템플릿은 음식점·카페·숙박·오프라인 소매·전자상거래·서비스·크리에이터와 공통 경로를 포함한다. 업종 템플릿은 필요한 질문과 조사 맥락을 바꾸는 장치이며, 각 업종에서 효과가 입증된 전문 컨설팅 모델을 뜻하지 않는다.

2026-11-10 전략 검토가 제안한 초기 판매 가설은 더 좁다. 미국의 반복 마케팅 업무가 있는 작은 판매팀이 확인한 상품 사실과 지난 승인 기준을 사용해 다음 캠페인의 메시지·시안을 준비하고, 승인·사용·결과 검토까지 이어 가게 하는 상품이다. 검토 문서는 이미 판매 중인 소형 온라인 브랜드 한 범주, 1~5명 팀, 월 2회 이상 캠페인을 하나의 모집 실험 예시로 제안한다. 이는 확정된 고객군이나 검증된 지불 의사가 아니다.

따라서 보고서에서는 세 층을 나누어 설명하는 것이 정확하다.

1. **장기 비전:** 사업 이해와 실행·학습을 연결하는 작업 공간.
2. **초기 상품 가설:** 한 고객군의 반복 캠페인을 승인·내보내기까지 끝내는 제공 범위.
3. **최신 상품 계획:** 작은 일회성 첫 캠페인, 반복 캠페인 구독, 선택형 AI 장면 추가 구매를 분리한 이미지·영상 크리에이티브 상품.

11/12 상품의 가치 제안은 브리프·문구·이미지·편집에 일관된 상품 맥락과 브랜드 표현을 적용하고, 버전 검토와 내보내기를 명확하게 제공하는 것이다. $19 일회성 상품은 처음부터 월 구독을 선택하는 부담을 낮추려는 구조이고, Focus/Growth는 반복 제작 루틴을 대상으로 한다. 가격 설계 의도와 실제 고객 반응은 구별해야 한다. 최신 상품은 여전히 판매 준비 상태다.

대표 개인의 목표 매출·실수령액은 운영 경제성을 판단하는 내부 제약이다. 고객이 구매하는 결과와 분리해야 한다. 투자 유치 역시 선택 가능한 자금 조달 경로이며 제품의 고객 가치나 달성된 실적이 아니다.

## 3. 고객이 이 프로젝트를 통해 얻을 수 있는 결과

### 3.1 현재 기능 기반의 구체적 결과

현재 구현의 가치는 사업 성공을 자동 보장하는 데 있지 않다. 고객이 직접 확인하고 사용할 수 있는 판단·작업·기록을 만든다는 점에서 설명해야 한다. 텍스트 생성에는 실제 공급자 설정과 권한이 필요하며, 결제/메일/미디어는 코드 존재와 운영 가용성이 다르다.

| 고객의 상황 | 현재 제품이 제공하는 결과 | 완료를 확인하는 기준 | 한계 |
|---|---|---|---|
| 무엇부터 볼지 모름 | 고민·업종·단계에 맞는 첫 조사 방향과 작은 다음 행동 | 가입 전에 첫 방향을 보고 다음 행동을 설명할 수 있음 | 원인 확정이나 전문 진단 아님 |
| 사업 정보가 흩어져 있음 | 저장된 상품·고객·채널·목표와 근거 묶음 | 프로필·측정값·진단 스냅샷을 다시 확인 | URL 자동 수집·외부 데이터 자동 검증 없음 |
| 해야 할 일을 정리하고 싶음 | 진단 권장 행동에 연결된 주간 목표·기한·상태·평가 지표 | 해당 주에 수행할 과제와 측정할 항목이 저장됨 | 완료율은 활동 관리이며 사업 개선 점수 아님 |
| 마케팅 표현 초안이 필요함 | 훅·광고 문구·숏폼 텍스트 대본·CTA, 선택 가능한 패키지 | 실제 공급자 호출 후 초안 작업과 결과물이 저장됨 | 무료 생성 권한 없음; 실공급자 품질·비용 실측 필요 |
| 문구를 수정·검토해야 함 | 수정 이력과 정확한 버전의 승인본, 복사/텍스트 다운로드 | 승인 대상 버전과 내려받은 버전이 일치 | 사람의 사실·권리·표현 검토 필요; 자동 게시 아님 |
| 업로드한 상품 사진으로 광고 이미지를 준비하고 싶음 | 사진·로고·헤드라인·설명·가격·CTA·브랜드색을 저장한 버전과 PNG/JPG 내보내기 코드 | 정확한 저장본 승인 후 1:1(1080×1080), 4:5(1080×1350), 9:16(1080×1920) 파일 작업을 확인 | 워커·활성 크리에이티브 권리 필요; 신규 판매는 여전히 닫힘. AI 생성/영상 아님 |
| 다음 작업에서도 표현을 유지하고 싶음 | 같은 계정·같은 사업의 최근 승인본 최대 3개를 선택적 스타일 참고로 사용 | 참고한 정확한 버전의 스냅샷이 작업에 남음 | 자동 모델 학습·성과 학습 아님; 지난 가격/효능을 현재 사실로 재사용하지 않도록 제한 |
| 실행 후 무엇이 달라졌는지 보고 싶음 | 실제 사용 기록과 기간·출처·통화가 있는 측정표·그래프 | 측정값의 정의와 비교 가능성을 확인할 수 있음 | 수기 기록; 자동 분석 도구 연결이나 인과적 기여 판정 없음 |
| 다음 행동을 다시 판단하고 싶음 | 새 결과를 근거로 한 재진단과 과거 결정의 맥락 | 새 진단과 이전 스냅샷을 별개로 보존 | 결과 개선이 NEXORA 효과라는 결론은 별도 실험 필요 |

### 3.2 준비 중인 미디어 상품이 제공하려는 결과

최신 공개 계획의 최종 산출물은 상품 사진/AI 시각 소재와 헤드라인·가격·로고·CTA를 조합한 광고 이미지(PNG/JPG), 사진을 장면으로 배치하고 움직임·전환·자막·음성을 넣은 최대 30초 완성 MP4, 별도 구매한 8초 AI 장면을 활용한 편집이다. 같은 디자인을 여러 규격으로 리사이즈해도 새 디자인 여러 개로 세지 않는 정책이다.

고객의 관점에서는 '한 상품의 메시지와 이미지·영상이 서로 어울리고, 검토할 버전과 내보낼 파일이 분명한 캠페인 패키지'가 목표다. 11/12 현재 업로드 사진 기반 정적 광고 이미지는 비공개 저장·정확한 저장 버전 승인·로컬 워커·3가지 비율 PNG/JPG 내보내기 코드와 검사를 갖췄다. 다만 신규 유료 크리에이티브 판매가 닫혀 있어 일반 신규 가입자의 현재 구매 가능 서비스로 설명해서는 안 된다. AI 이미지 생성, 완성 MP4, 음성 합성, AI 장면 생성은 여전히 미구현이다. 공개 계획을 모두 현재 납품 가능한 서비스로 표현하면 안 된다. 실제 영문 품질·브랜드 일치·상품 사실·소재 권리·파일 품질·실사용 가능성을 실제 공급자와 검증해야 한다.

### 3.3 기대할 수 있으나 아직 입증되지 않은 효과

작업 사이의 도구 이동 감소, 반복 설명 감소, 승인까지 걸리는 시간 단축, 브랜드 표현의 일관성, 수정 부담 감소, 다음 행동의 명확성은 제품 구조가 추구하는 고객 효과다. 저장·버전·승인·연결 기능이 그 효과를 낼 수 있는 기반은 있다. 그러나 실제 고객 대상 절감 시간·총비용·수정 횟수·승인 속도·반복 사용·유료 갱신·매출·전환율·광고수익률 개선 수치는 조사 자료에서 입증되지 않았다.

특히 **고객이 얻는 직접 산출물**, **그 산출물로 업무를 쉽게 끝내는 효과**, **사업 매출·이익의 개선**은 다른 수준의 결과다. 첫째는 기능으로 확인할 수 있고, 둘째는 실제 고객 과제와 비교해야 하며, 셋째는 외부 요인과 인과적 기여를 고려해 별도로 검증해야 한다. 다운로드·과제 완료·조회수·회원가입을 판매 성과로 계산하면 안 된다.

## 4. 고객 여정 상세

1. 공개 랜딩에서 자신의 고민과 제품 범위를 확인한다. 허구 사업의 메시지·채널 미리보기를 조작하거나 `/demo`·공개 가이드로 사용 방식을 살펴볼 수 있다. 이 예시는 실제 생성·업로드·고객 실적이 아니다.
2. `/start`에서 고민·업종·단계를 고른다. 사업 설명과 실제 숫자는 선택 사항이다. 첫 조사 방향을 가입 전에 볼 수 있다.
3. 답과 진행 단계는 해당 탭의 sessionStorage에 남는다. 미완성 체크는 멈춘 단계에서, 완료한 체크는 결과에서 재개한다. 가입만으로 사업 답이 계정에 전송되지 않는다.
4. 사용자가 명시적으로 저장하면 프로필·측정값·진단을 계정에 함께 저장한다. 기존 계정 정보 갱신은 버전과 확인 절차를 사용한다.
5. `/workspace`의 기본 화면에서 현재 방향, 검토할 초안, 실제 사용 기록이 없는 승인본, 남은 계획, 새 결과 등 다음 작업을 확인한다. 자세한 진단과 설정은 필요할 때 연다.
6. 상세 프로필은 다섯 단계 안내로 보완한다. 모르는 정보는 비워 둘 수 있다. 맞춤 텍스트 제작에는 저장된 진단에 상품·고객 설명·판매 채널이 필요하다.
7. 권장 행동을 주간 목표로 만들고 기한·지표·노트·정확한 관련 결과물 버전을 연결한다. 광고보다 자료 수집이나 비용 검토가 먼저일 수 있다.

## 8. 남은 과제와 우선순위

사용자 방침을 반영한 최신 문서는 고객 반응·반복 사용·가격 수용성을 출시 후 개선에 사용한다고 명시한다. 따라서 사전 고객 설문을 새로운 출시 필수조건으로 강제하면 안 된다. 다만 공개적으로 약속한 납품·계정·결제·저장·운영 최소 요건은 출시 전에 갖추어야 한다.

### 출시 전에 마무리할 제공/운영 요건

1. 업로드 사진 기반 이미지의 저장·승인·출력·이미지 예약 원장은 최신 코드로 추가됐다. 남은 AI 이미지/영상/음성/AI 장면의 제작·실패·사용량·상품 권한 연결을 완성하고 실제 공급자로 확인한다. 이미지 원장이 캠페인·영상·장면 원장까지 구현한 것은 아니다.
2. 실제 AI·Stripe·Resend 계정과 모델·가격·웹훅·메일 도메인을 연결하고 성공/실패/취소/갱신/환불/복구를 확인한다. 시험 모형의 성공을 실제 연결 증명으로 보지 않는다.
3. HTTPS 주소, 영구 디스크의 단일 Node 인스턴스, 보호된 DB·미디어 저장소를 운영 환경에서 확인한다. 온라인 백업·검증·격리 복원·health/readiness 코드는 추가됐다. 운영 백업 스케줄·외부 사본·보관 기간·실제 권한·알림 수신처·장애 책임자와 실제 운영 복구 확인은 남아 있다.
4. 실제 법적 판매자·지원 창구·약관·개인정보·환불 범위·소재 권리와 세금 처리 방식을 확정한다. 구독/추가 결제와 최대 사용량을 고객에게 명확히 안내한다.

## 8.1 고객의 일주일 활용 예시 — 설명용 가정 사례

다음은 고객 실적이나 이미 실행한 프로젝트가 아니다. 미국에서 상품을 판매하는 소규모 온라인 브랜드가 다음 주말 한 상품을 소개하려는 상황으로, 현 기능과 미구현 범위를 구분해 설명한 가상 시나리오다. 현재 신규 크리에이티브 구매가 닫혀 있으므로 이미지 출력은 해당 권리와 워커가 유효한 검증/운영 조건을 전제로 한다.

| 요일 | 고객이 하는 일 | NEXORA에 남는 직접 결과 | 유의점 |
|---|---|---|---|
| 월요일 | 현재 고민·상품·고객·채널을 정리하고 실제 방문/주문 기록을 확인 | 첫 조사 방향, 프로필, 기간·출처 있는 근거와 진단 스냅샷 | 기록이 없으면 모르는 값으로 남김; 전환 부진 원인을 확정하지 않음 |
| 화요일 | 한 상품 소개를 주간 과제로 정하고 메시지 방향을 고름 | 평가 지표와 기한이 있는 목표, 유료 텍스트 권한/공급자 설정 시 문구 초안 | 상품·고객·판매채널 정보와 실제 생성 권한 필요 |
| 수요일 | 문구를 수정해 사실·가격·CTA를 확인하고 정확한 버전을 승인 | 승인 텍스트와 수정 이력; 업로드 사진·로고를 포함한 저장된 이미지 디자인 | 소재 권리와 상품 사실을 고객이 확인 |
| 목요일 | 이미지 저장본을 승인하고 필요한 비율의 PNG/JPG를 요청 | 권한/워커가 유효하면 1:1·4:5·9:16 파일과 작업 상태 | 리사이즈를 새 디자인 여러 개로 세지 않음; MP4 제작은 미지원 |
| 금요일 | 승인 문구·이미지를 다운로드해 고객이 외부 채널에서 직접 사용 | 실제 사용했다는 별도 고객 기록 | 다운로드 자체는 게시·광고비 집행·판매 기록이 아님 |
| 토/일요일 이후 | 충분한 관측 기간이 지난 다음 동일 정의의 방문·주문·광고비를 입력 | 기간·출처 있는 측정값과 다음 조사/재진단의 근거 | 하루 이틀의 변화만으로 인과 효과를 결론 내리지 않음 |

이 과정을 통해 고객이 직접 얻는 결과는 '일정이 있는 한 작업, 확인하고 승인한 문구/정적 이미지 파일, 사용 기록, 다음 검토에 쓸 근거'다. 작업 시간이 줄었는지와 실제 주문이 늘었는지는 이 시나리오의 약속이 아니라 관찰해야 할 결과다.

## 9. 종합 PDF에 권장하는 방향/결과 설명문

**프로젝트 방향:** NEXORA는 소규모 사업자가 자신의 상품과 고객을 이해한 내용을 실제 캠페인 작업과 연결하고, 사람이 승인한 결과물을 사용한 뒤 관측 결과를 다음 행동으로 이어 가도록 돕는 작업 공간을 지향한다. 초기 상품은 반복 마케팅 업무를 위한 캠페인 패키지에 초점을 맞추며, 기존 사업 체크·계획·측정·이력 기능이 그 작업의 맥락을 보존한다.

**고객이 얻는 결과:** 현재 기반에서는 다음에 조사할 질문과 주간 과제, 검토·수정·승인한 텍스트와 기록을 얻는다. 최신 코드에는 업로드한 상품 사진과 로고로 만든 정적 광고 이미지를 정확한 버전으로 승인하고 PNG/JPG로 내보내는 구조가 추가됐다. 전체 크리에이티브 상품의 판매는 아직 닫혀 있고, AI 이미지·짧은 영상·음성·AI 장면 제작은 준비 중이다. 반복 설명과 수정의 감소, 승인까지의 시간 절감이 목표이며, 실제 절감 시간·매출·광고 성과의 개선은 출시 후 고객 업무에서 확인해야 한다.

이 문장은 현재의 고객 가치와 미래 제공 의도를 함께 설명하되, 준비 중 상품을 현재 납품 가능 상태로 확대하지 않는다.
