B02 개발 상품 버전과 서버 권한
새 미디어 계약과 기존 텍스트 계약을 구분한다. 서버가 가격·통화·주기·상품 버전과 포함량을 결정

B03 공동 세금·판매 정보
실제 판매자 주소·상품 분류·필요 등록·청구 주소 수집·약관 동의를 설정한다. Stripe Tax의 계산 기
능과 등록·신고·납부 책임을 구분한다.
B04 개발 웹훅과 월 권한
현재 구독·청구서 결제 상태로 권한과 기간을 동기화한다. 성공 URL만으로 권한을 주지 않는다. 이
벤트 재전송·순서 변경에도 중복 지급하지 않는다.
B05 공동 갱신·해지·청구서 포털
고객이 결제 수단·청구서를 확인하고 기간 말 해지를 할 수 있게 한다. 미구현 플랜 변경·수량 변경·
일시정지는 포털에서 끈다.
B06 개발 사전 결제 동작 확인
Stripe sandbox와 테스트 결제로 결제 완료·실패·구독 취소·권한 반영을 확인한다. 실제 카드를 이
용한 live 모드 테스트 결제는 요구하지 않는다. [1]
B07 공동 운영 설정 전환
운영 키·Price ID·포털·웹훅 서명을 연결한다. 새 계약의 배포가 완료된 뒤 준비 중 상태와 결제 버튼
을 함께 전환한다.
웹훅 수신 경로: /api/billing/webhook . 실제 처리 중인 subscription·invoice·checkout 이벤트와 Stripe 설정을 맞춘다. 테스트용 키·Price·웹훅
비밀값은 운영용과 분리한다. 첫 실제 고객 결제부터 운영 청구서와 권한 반영을 확인한다.

07 / HOSTING, EMAIL & OPERATIONS 운영 환경 구성
계정과 파일이 유지되는 서버에 배포한다.
현재 코드에 맞춘 초기 구성은 Node.js 애플리케이션 1개 + 영구 디스크의 SQLite + 별도 미디어 작업 처리기 +
비공개 파일 저장소다. 처리량이 커지면 이후 확장한다.
ID 담당 준비 내용과 완료 기준
O01 개발·대표 Node·실행 환경
Node.js 24.14 이상과 빌드 환경을 준비한다. 필요한 영상 렌더러·폰트·음성 구성과 작업 처리기
가 실제 서버에서 실행된다. SQLite를 유지할 경우 단일 앱 인스턴스와 호환되는 배포를 사용한
다.
O02 대표·개발 공개 주소·HTTPS
도메인 DNS, 인증서, 프록시, HTTPS를 연결한다. 앱 주소·메일 링크·결제 반환 주소·사이트 URL
이 같은 운영 도메인을 쓴다.
O03 개발 DB·파일 지속 보관
DB를 배포 때 사라지지 않는 보호 경로에 둔다. 원본과 완성 파일을 지속 저장한다. 재배포 후
계정·프로젝트·파일이 그대로 열린다.
O04 대표·개발 메일 도메인·발신
Resend 도메인을 인증하고 안내된 DNS 레코드를 적용한다. 인증·비밀번호 복구 메일이 실제 메
일함에 도착하며 운영 주소의 링크가 열린다. 중요한 계정 링크의 클릭 추적은 끈다. [4]
O05 개발 인증·접근·비밀값
HTTPS 세션 쿠키와 로그아웃·비밀번호 복구를 확인한다. 고객별 파일·프로젝트 접근을 분리한
다. 공급자 키·메일 토큰·카드 정보가 브라우저나 로그에 노출되지 않는다.
O06 개발 백업·복원·배포 되돌리기
일관된 SQLite 백업과 파일 보관 방법을 마련한다. 별도 경로에서 백업을 열 수 있고, 이전 앱 버
전과 호환되는 데이터 변경·복구 절차가 있다.
O07 공동 운영 알림·지원 대응
서버·작업 처리기·생성 실패·결제 웹훅·저장소·공급자 지출을 볼 수 있다. 알림 수신자와 신규 구
매/새 생성 중단 방법을 정한다.
초기 출시에서 생략할 수 있는 것
다중 리전·마이크로서비스·대규모 관측 플랫폼·복잡한 고객 분석 SDK·모든 업무의 자동화는 필요하지 않다. 단일 서버로 시작하더라도
지속 저장, 기본 알림, 고객 지원 창구는 준비한다.
현재처럼 서버 API·세션·DB를 쓰는 앱 전체를 정적 HTML 파일만 업로드하는 방식으로 배포하지 않는다. Next.js의 Node 서버 배포 절차와 현
재 SQLite 구성에 맞는 호스팅을 사용한다.
