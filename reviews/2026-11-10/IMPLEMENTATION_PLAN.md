# NEXORA 실행 계획·구현 한계

검토일: 2026-11-10. 이 문서는 제안 백로그이며 앱에 아래 기능을 구현했다는 보고가 아니다. 기존 작업 트리와 운영 데이터를 보존하고 검토 산출물만 추가했다.

## 1. 우선순위

첫 목표는 ‘세계적인 AI 플랫폼 기능 목록’의 완성이 아니라 **같은 고객이 첫 작업을 실제 사용하고 다음 작업에도 돈을 내는 흐름**의 완성이다.

| 순서 | 할 일 | 완료 조건 | 의존성 |
|---|---|---|---|
| P0-1 | 첫 고객·반복 과제·유료 제공 범위 확정 | 최근 실제 업무, 결정권자, 다음 일정, 자료·사용 채널을 확인한 고객 모집 기준 1개 | 대표의 접근 가능 고객·현장 조사 |
| P0-2 | 제품 퍼널·과제 단위 기록 | 시작·승인·실제 사용·후속 과제·결제를 구별. 중복 사건 방지와 관찰 기간 정의 | 분석 보관 정책, 실제 결제는 외부 연동 필요 |
| P0-3 | 하나의 캠페인 작업 흐름 | 브리프→최소 사실 확인→메시지 선택→정확한 버전 승인→내보내기·사용 확인을 이어서 수행 | 기존 프로필·진단·버전·소유자 범위 재사용 |
| P0-4 | 고객용 결과물 미리보기 | 고객이 사용할 채널 문맥에서 결과를 보고 수정. 예시·실제 결과·미지원 기능을 명확히 표시 | 실제 상품 사실과 소재 권리 |
| P0-5 | 운영 가능한 유료 파일럿 | 정확한 가격·범위·지원·환불 안내, 실제 대금 수취와 환불·결제 확인, 제공 시간 기록 | 결제 사업자·사업 정보·운영 계정 |
| P0-6 | 상업 이용의 기본 회복·원가 관리 | 계정 회복, 생성 실패 안내, 전체·계정별 지출 상한, 비용 추적·지원 경로 | 이메일·AI 계정·운영 예산 |
| P1-1 | 확인된 브랜드 기억 | 승인한 문구·수정 이유를 사용자가 재사용 조건으로 확인. 다음 요청에 포함하고 원본 버전 추적 | 사실·선호·성과를 분리한 자료 구조 |
| P1-2 | 재방문 홈·다음 일정 | 승인 대기, 다음 과제, 새 결과가 우선 표시. 고객 선택 일정으로 안내 | 실제 반복 업무와 선택형 알림 동의 |
| P1-3 | 자료 가져오기 | 우선 CSV 미리보기·열 매핑·기간·통화·중복 확인. 필요한 경우 외부 읽기 전용 연결 1개 | 실제 내보내기 양식·데이터 권한 |
| P1-4 | 코호트·월간 가치 요약 | 두 번째 별도 과제, 두 번째·세 번째 결제, 지원 시간, 직접 원가 연결 | 충분한 관찰 기간의 실제 고객 |
| P1-5 | 사용성 세부 수정 | 뒤로 가기·이어하기·미저장 표시·대비·모션·모바일 계획 탐색 개선 | [UI 검토 U11~U18](UX_REVIEW.md) |
| P2 | 팀 권한·연동 확대·시각 제작 | 기존 유료 고객 요청·추가 지불·운영 원가가 확인된 기능만 확대 | 앞선 코호트의 결과 |

페이지 경로를 전부 바꾸거나 기존 자료를 새 구조로 강제 이전할 필요는 없다. 별도 ‘캠페인’ 단위를 추가하고 기존 진단·결과물 버전·사용·지표의 정확한 ID를 연결하는 방식부터 검토한다. 기존 스냅샷과 과거 통화는 유지한다.

## 2. 기존 구조를 어떻게 발전시킬 것인가

현재 재사용 가능한 기반은 소유자별 기록, 프로필 버전, 진단 스냅샷, 생성 요청 중복 방지, 버전별 승인, 실제 사용 기록, 결과를 근거로 옮기는 구조다. 이 구조는 버릴 이유가 없다.

추가할 최소 자료는 다음과 같다.

| 자료 | 저장할 내용 | 제품상 목적 |
|---|---|---|
| 캠페인 과제 | 상품·목표·채널·일정·연결 진단/행동·관련 결과물 버전 | 흩어진 도구를 하나의 고객 업무로 연결 |
| 확인한 사업 사실 | 출처·확인일·적용 범위·고객 수정·버전 | 오래된 가격·상품 조건을 새 작업에 잘못 사용하지 않음 |
| 승인한 표현 규칙 | 유지할 표현·금지할 표현·수정 이유·승인자·범위 | 다음 생성의 반복 설명과 수정 감소 |
| 작업 평가 | 사실 오류·브랜드·형식·수정 시간·실제 사용 여부 | 모델·프롬프트 변경의 품질 회귀 평가 |
| 원가 기록 | 작업별 토큰·제공자·가격표 버전·외주·저장·실패·지원 시간 | 실제 고객별 손익·예산 상한 |
| 제품 이용 사건 | 과제·버전·행동·시각·출처·중복 방지 키 | NEXORA 자체 퍼널과 유지율 |
| 결제·권한 상태 | 검증된 결제 사건·계약 기간·상품 범위·환불·취소 | 무료·유료 권한과 청구 복구 |

모든 기존 결과물을 다음 프롬프트에 무제한 넣는 방식은 적합하지 않다. 확인된 사실·선호·거절한 주장·관찰 결과를 구분하고 현재 과제에 필요한 부분만 사용한다. 고객이 기억을 수정·삭제하거나 특정 작업에서 제외할 수 있어야 한다. 고객 간 자료 공유·학습 권한을 자동으로 가정하지 않는다.

수치 비교는 계속 정형 계산으로 수행한다. AI는 확인된 맥락의 요약·가설·표현 제안에 쓴다. 고도화의 완료 조건은 ‘AI 진단을 추가했다’가 아니라 근거 오류를 늘리지 않고 실제 선택·수정 부담을 줄이는 것이다.

## 3. 실행 일정과 판단 기준

다음은 준비 순서 제안이다. 개발 인력·고객 접근·외부 심사에 따라 달라지므로 완료일 보장이 아니다. 고객을 모집하는 일과 제품 작업을 함께 진행한다.

| 기간 | 제품 작업 | 사업 검증 | 다음 단계 조건 |
|---|---|---|---|
| 1~2주 | 구체적 업무 랜딩·가격/범위 설명·이용 사건·비용 기록 설계 | 적격 고객 10~15명 인터뷰, 실제 최근 작업 관찰 | 반복 업무·대체 비용·지불 이유가 설명됨 |
| 3~4주 | 최소 캠페인 흐름·채널 미리보기·명시적 저장·내보내기 | 동일 유형 5~10명에게 제한된 유료 제공 | 실제 결제와 결과물 사용, 수정·지원 시간 확보 |
| 5~8주 | 승인 규칙 재사용·다음 과제 홈·자료 입력 축소 | 같은 자격의 유료 코호트 확대, 두 번째 작업·결제 관찰 | 반복 수요가 실제로 있고 원가를 설명할 수 있음 |
| 9~12주 | 반복 실패 수정, 필요한 연결 1개, 월간 가치 요약 | 세 번째 결제·유입 채널 1~2개의 재현성 확인 | 유지·획득비·고객별 원가를 연결해 확장 판단 |

1~2주의 인터뷰 10~15개, 첫 파일럿 5~10개는 학습 규모 제안이다. 고객이 자연스럽게 반복 업무를 하지 않는다면 일정을 맞추기 위해 억지 사용을 요청하지 않는다. 두 번째 월 결제와 첫 사용 후 30일 결과는 실제 관찰 기간이 지난 계정만 분모에 포함한다.

초기 탐색에서는 20개 유료 계정의 7일 실제 사용 14개, 30일 별도 과제 10개, 두 번째 결제 12개 같은 내부 기준을 사전 합의할 수 있다. 첨부 확장판 p.26에도 비슷한 예가 있다. **이는 월 이탈률 3%를 입증하는 기준이 아니다.** 두 번째 결제가 60%인 작은 탐색 집단을 보고 97% 월 유지율로 사업 계획을 세우면 안 된다. 이후 더 큰 동질 코호트와 세 번째 이후 결제를 관찰하고 경제성 모델의 3% 가정을 실측으로 교체해야 한다.

같은 과제를 기존 방식으로 하는 총시간과 NEXORA의 입력·대기·수정·승인·내보내기를 모두 포함한 시간을 비교한다. 순서를 번갈아 학습 효과를 줄이고, 익숙한 기존 도구와 결과 품질도 함께 기록한다. 고객의 단순 선호를 정확도나 매출 효과로 바꾸지 않는다.

## 4. 진행·수정·중단 조건

| 관측 | 해석할 가능성 | 다음 행동 |
|---|---|---|
| 결제하지만 결과물을 사용하지 않음 | 품질·형식·사용 경로·기대 차이 | 생성량보다 실제 사용 방해 요소 수정 |
| 첫 사용은 하지만 후속 과제가 없음 | 업무 빈도·고객군·상품 형태 불일치 | 일회성 판매와 반복형을 분리, 고객 기준 재검토 |
| 반복 사용하지만 결제하지 않음 | 무료 대안 대비 편익·가격·결정권 문제 | 적격 고객과 판매 범위·가격 재검증 |
| 결제 유지에 과도한 사람 개입 필요 | 소프트웨어보다 인력 대행에 가까운 원가 | 유료 지원 분리·작업 범위 축소·제공 방식 변경 |
| 성과 자료가 적거나 정의가 다름 | 효과 판단 불가 | 인과 효과 주장을 보류하고 시간·품질 편익부터 검증 |
| 광고로만 유입이 늘고 원가 회수 전 해지 | 획득 지출이 지속 불가능 | 광고 확대 보류, 유지·고객군·제공 가치부터 수정 |
| 고객이 기존 플랫폼 AI로 충분하다고 반복 응답 | 독립 구독 이유가 약함 | 추가 개발보다 해결 과제·파트너 고객군 재선정 |

이탈 방지는 해지를 어렵게 만드는 작업이 아니다. 일시정지·일회성 전환·쉽게 가능한 취소·내보내기를 제공하고, 품질 문제를 할인이나 장기 결제로 가리지 않는다.

## 5. 지금 구현할 수 있는 것과 외부에서 해결할 것

‘지금 만들 수 없다’는 말에는 서로 다른 이유가 있다. 코드로 만들 수 있으나 아직 작업하지 않은 기능, 계정·심사·운영자가 있어야 작동하는 기능, 현실의 고객 반응이 있어야 입증되는 결과를 구분한다.

| 항목 | 지금 가능한 작업 | 현재 대화·로컬 코드만으로 끝낼 수 없는 부분 |
|---|---|---|
| 화면과 작업 흐름 | 업무 중심 랜딩·캠페인 카드·미리보기·반응형·모션·접근성 개선 구현 | 고객이 더 쉽고 재밌게 느끼는지, 실제 이탈 개선 여부 |
| 브랜드 기억 | 확인·수정·삭제 가능한 규칙, 다음 요청 적용, 회귀 평가 구현 | 고객의 실제 승인 기준과 반복 사용 효과 |
| 고도화된 판단 | 근거 자료와 가설을 연결하는 구조·평가 도구·프롬프트 구현 | 업종별 정확도, 원인 규명, 전문가 검토와 실제 자료 |
| 외부 AI 생성 | 제공자 어댑터·실패 처리·한도·원가 기록 | 실제 계정·예산·모델 접근, 고객 자료의 전송 범위, 실제 품질 |
| 완성 이미지·영상 | 생성·업로드·편집·내보내기 흐름과 검수 인터페이스 | 유료 제공자·소재 권리·브랜드 정확성·단가·실제 완성도 |
| 스토어·분석 연결 | CSV 검토 가져오기, 읽기 전용 연결 코드·토큰 보관·재동기화 처리 | 고객 계정 권한·실제 양식·외부 앱 등록/심사·서비스 정책 |
| 결제 | Checkout·웹훅 검증·중복 방지·상품 권한·취소/환불 흐름 | 판매자 자격·계정 개설·지급 계좌·실제 요율·세금·환불 운영 |
| 이메일·계정 회복 | 토큰 만료·일회성 처리·재설정 화면·개인정보 노출 방지 | 발송 계정·도메인 인증·배달 품질·지원 담당자 |
| 알림 | 선택형 일정·빈도·시간대·해지 설정·중복 발송 방지 | 발송 서비스·고객 동의·실제 알림 편익 |

| 운영 배포 | 배포 설정·관측 도구·복구 절차 준비 | 도메인·호스팅·지속 저장소·접근 권한·운영 책임 |
| 고객·파트너·VC | 인터뷰 문안·시연·원가표·피치·자료실 준비 | 실제 만남·신뢰·계약·자금·구매·투자 결정 |
| 목표 매출·대표 수령액 | 시나리오·월별 계획·검증 지표 계산 | 매출·유지율·수익·투자 유치를 보장하는 것 |

외부 연결은 코드를 만드는 것과 실제 운영을 여는 것을 구분해야 한다. 이번 검토에서는 비밀키를 읽거나 노출하지 않았고, 외부 고객 연락·결제·광고·공개 게시를 실행하지 않았다.

## 6. 기술·운영 관점에서 우선 확인할 제한

- **저장소:** 현재 SQLite WAL·단일 인스턴스·지속 디스크 구조는 소규모 파일럿에서 사용할 수 있다. 고객 200개라는 숫자만으로 재개발하거나 DB를 교체할 이유는 없다. 그러나 임시 디스크 배포, 서로 다른 디스크의 다중 인스턴스, 복구하지 못한 백업은 상업 운영 문제다. 실제 사용량·동시 쓰기·장애 복구를 확인한 뒤 확장한다.
- **계정:** 소유자별 조회와 해시 암호·세션 쿠키·동일 출처 검사는 기반 장점이다. 공개 유료 운영의 계정 확인·복구·지원·삭제는 별도로 완성해야 한다. 현재 작업 공간 내보내기를 새 기능처럼 다시 만들 필요는 없다.
- **원가:** 현재 토큰 사용 기록과 시간당 생성 횟수 제한은 있지만, 그것만으로 전체 금액 예산을 통제하지 못한다. 실패 비용·고사용 고객·계정 다중 생성도 고려한 서버 지출 상한이 필요하다.
- **배경 작업:** 긴 생성·재동기화·알림은 재시작·만료·중복·알 수 없는 제공자 결과에 대응해야 한다. 현재 요청 중복 방지·실패 기록을 살리되 외부 실행에 맞는 작업 처리 체계를 추가한다.
- **팀 기능:** 현재 개인 계정의 승인 상태는 팀의 역할별 승인·조직 자료 분리·감사 정책과 다르다. 실제 팀 수요가 생기면 별도 설계한다.
- **검색 유입:** 사이트 URL이 미설정이면 robots가 전체 크롤링을 막는 기본값이다. 의도된 출시 전 동작이다. 공개 출시 때 운영 URL·인덱싱·공유 미리보기를 확인해야 한다.

## 8. 대표가 다음에 결정할 핵심 사항

먼저 한 고객군과 한 반복 업무를 고르고 그 범위의 유료 파일럿을 진행하는 것을 권한다. 가격은 지불 이유와 제공 원가가 검증되기 전까지 가설로 관리한다. 목표 수령액에 맞춰 검수·지원 시간을 제한하고, 범위를 넘는 서비스는 별도 가격으로 제안한다.

제품 개발의 첫 묶음은 **캠페인 과제 단위, 실제 미리보기, 승인 기준 재사용, 제품 퍼널·원가 기록**이다. 그와 동시에 실제 고객이 결제·사용·재구매하는지 확인한다. 이미지·영상·게시·기업용 기능의 전면 확장은 이 결과를 보고 결정한다.
