# NEXORA 모바일 구현 계획

## 제품과 운영 방향

기존 GitHub 저장소 `upstagecorp-cell/upstage`를 웹·백엔드·모바일 소스의 운영 기준으로 사용한다. 기존 Next.js는 저장소 루트에 유지하고 Expo 소스는 `apps/mobile/`에 둔다. 변경은 별도 작업 브랜치에서 검증하며 main과 운영 DB를 직접 변경하지 않는다. 미리보기와 네이티브 빌드용 Manus Mobile 사본은 플랫폼 제약으로 별도 관리하므로 GitHub의 `apps/mobile/`과 내용·커밋을 명시적으로 동기화한다. 이 사본은 두 번째 제품 백엔드나 데이터 원본이 아니다.

## 범위 및 순서

1. 기존 Next.js 제품 규칙과 사용 권한을 유지한다. 현재 요청은 SQLite이며 Supabase PostgreSQL은 준비 단계다. 비동기 저장소 인터페이스, SQLite/PostgreSQL 구현 및 실제 양쪽 parity 검증을 통해 전환을 준비한다. 불완전한 경로를 production으로 전환하지 않고 기존 SQLite 및 롤백 경계를 보존한다.
2. `/api/mobile/v1`에서 웹 쿠키와 분리된 짧은 access token 및 회전·재사용 탐지·폐기가 가능한 refresh token, 소유자 권한과 일관된 오류를 제공한다. 원문 토큰은 저장·기록하지 않고 모바일 비밀 저장소를 사용한다. 데이터 저장소와 보안 검증이 끝나기 전 모바일 API와 결제 기능은 안전하게 닫는다.
3. Expo Router, React Native, TypeScript, TanStack Query, SecureStore를 사용해 영어 iOS/Android 앱을 구현한다. 기능은 고민·사업 정보와 첫 방향, Home의 다음 행동/주간 목표, Plan, Create의 생성·수정·정확한 버전 승인, Results의 실제 사용과 지표 입력·이전 결과 반영, Account의 계정·세션·알림 설정·삭제 요청·정책/지원이다. 접근성, 빈 상태, 저장/오류/재시도와 중복 방지를 포함한다. 백엔드 미완성 기능을 실제 성공이나 사용자 데이터로 가장하지 않는다.
4. 알림은 허가와 수신 거부를 존중한다. 미디어는 서버에서 소유권을 확인한 단기 signed URL만 사용한다. 무료·유료 entitlement 및 기존 웹 생성 규칙을 독단적으로 변경하지 않으며, 공급자 비용과 앱스토어 정책이 검증될 때까지 결제는 열지 않는다. 자동 게시·광고 집행·SNS OAuth 등 P2는 범위 밖이다.
5. 단위·계약·보안·회귀 테스트를 실시하고 실제 PostgreSQL·네이티브 기기·스토어 계정이 없는 검증 항목은 미완료로 남긴다. 실제 스토어 제출은 사용자 승인과 서명·정책·출시 게이트를 충족한 이후 별도 단계다.

## 구조

- 웹 저장소의 `src/lib/server/repository/`: 비동기 데이터 계약과 어댑터. 기존 `src/lib/server/` 요청 경로는 안전한 전환 전까지 유지.
- 웹 저장소의 `src/lib/server/mobile*` 및 `src/app/api/mobile/v1/`: 모바일 인증·소유권·API 계약. 원자적 작업과 권한은 서버에 둔다.
- GitHub `apps/mobile/` / Manus 모바일 사본: `app/` Expo Router 화면, `components/` 공통 UI, `lib/` API·인증·도메인 상태, `assets/` 아이콘. 서버 비밀과 원본 DB 자격 증명을 번들에 포함하지 않는다.
